# Archipelago

Chart what you understand about a domain, as islands in open water. Brief: `docs/BRIEF.md`. Slice 1 spec: `docs/superpowers/specs/2026-09-03-archipelago-slice1-design.md`. Plan: `docs/superpowers/plans/2026-09-03-archipelago-slice1.md`.

## Commands

```bash
bun install
bun test                              # all tests (bun test, NOT vitest — vitest cannot resolve bun:sqlite)
bun run test:wasm                     # core, server, web tests again on the WebAssembly SQLite (the hosted build's database)
bunx tsc --noEmit                     # typecheck
bun run src/cli/index.ts <command>    # the CLI; `bun link` registers it as `archipelago`
bun run src/cli/index.ts serve        # map server on 127.0.0.1:4480, opens the browser
bun run src/cli/index.ts serve --stub # judge without a Claude login
bun run src/cli/index.ts serve --judge api   # judge on the Messages API (needs ANTHROPIC_API_KEY)
bun run build:web                     # the hosted build: a static site in dist/web/ (serve it on localhost to try it)
bun run deploy:web                    # build, then `wrangler pages deploy` to the Cloudflare Pages project archipelago (https://archipelago-c24.pages.dev)
bun run src/cli/index.ts export [--out f]   # the whole database as one file (VACUUM INTO); the hosted app imports it
claude plugin validate .              # the plugin and marketplace manifests
claude --plugin-dir .                 # try the plugin from this checkout
```

## Architecture

Two brains, one database. Claude in the terminal is the cartographer (skill → CLI → SQLite): it sketches islands, islets, and straits. The judge runs inside the server (`src/server/judge/`), one thread per island, on one of three runners behind `JudgeRunner`: `api` (the Messages API, `api.ts`), `sdk` (the Claude Agent SDK, `sdk.ts`), or `stub`, and writes verdicts through the same repositories. The mentor runs on the same runner as a second persona (`src/server/judge/persona.ts`: protocol file, closed tool list, renderers, stub), with its own thread per island (`messages.mode`), its protocol in `MENTOR.md`, and a learner block (solid ground across every domain, confirmed reefs, the note in `learner`) at the top of its context. The browser is the consumer (server → JSON API → canvas page polling `/api/version`) and the judge's chat surface (`POST /api/probe` streaming server-sent events). The outline (`outline.js`) reads `GET /api/outline`, the whole tree, refreshed with every snapshot. Comments and focus flow back through the same database.

## Conventions

- Plugin: the repo root is the plugin. `plugin.json` points `skills` at `./.claude/skills`, so the same SKILL.md serves the plugin and the in-repo project skill; it calls `archipelago`, never `bun run src/cli/index.ts`. Claude Code installs dependencies from `package.json` + `bun.lock` with `--ignore-scripts` and a 60 s limit, so every dependency is pinned exactly and nothing may need an install script. Mermaid is committed at `src/server/vendor/mermaid.min.js` (a devDependency; `bun run vendor:mermaid` refreshes it) because it was the slowest download. Bump `version` in `plugin.json` to ship an update.
- One database per user: `~/.archipelago/archipelago.sqlite` (`DEFAULT_DB_PATH`), `ARCHIPELAGO_DB_PATH` overrides.
- `bun:sqlite`, numbered migrations in `src/core/migrations/`, snake_case columns aliased to camelCase in every `select`. Repositories type their connection as `Database` from `src/core/sql.ts` (the subset they use), never from `bun:sqlite`, so they also run on the WebAssembly adapter `sql-wasm.ts`; `bun run test:wasm` proves it by swapping `openDatabase` for the adapter across the core, server, and web suites.
- Open water is the absence of a verdict. Never store or render an "open" state as a score.
- Verdicts are append-only; latest `id` wins. Island slugs are unique per domain. Straits join siblings only.
- Every write bumps `view_state.version` via SQL triggers; the page polls that integer every 2s.
- CLI: JSON always; pretty on a TTY, compact with `--json` or when piped; `--stdin` merges JSON under flags; errors exit 1 with `{ error, valid? }`.
- Server opens and closes the database per request. Static files are read fresh (`Cache-Control: no-cache`); no build step for the page.
- Hosted build (spec `docs/superpowers/specs/2026-10-20-hosted-byok-design.md`): the same page and the same `/api/` routes, with the server in a Web Worker. `api-routes.ts` holds everything under `/api/` and must stay free of Bun and Node calls; `routes.ts` adds static files and vendor bundles for `archipelago serve`. The page's requests all go through `transport.js` (`request`): `fetch` locally, a message to `/worker.js` when `index.html` sets `ARCHIPELAGO_HOSTED` (only `build:web` does). The worker (`src/hosted/worker.ts`) takes the `archipelago-db` Web Lock, opens SQLite-WASM on OPFS (`opfs-sahpool`) once, migrates, and answers through `handler.ts`; `build-web.ts` swaps three modules for browser twins (`core/db.ts` → `hosted/db.ts`, `judge/protocol.ts` → `hosted/protocol.ts`, `judge/sdk.ts` → `hosted/no-sdk.ts`). Paths under `/hosted/` are the worker's own (`hosted/routes.ts`): `settings` (the key, the model, remember, stub), `export`, `import`; a database file crosses the transport as bytes (`application/vnd.sqlite3`). The key lives in the worker (`settings.ts`: IndexedDB when remembered, else memory), never in SQLite, and the page reads back only `…abcd`; with a key the judge is `createApiRunner({ apiKey, model, hosted: true })` (Sonnet 5.5 by default, `MODELS`), without one the stub. `src/web/hosted.js` is the page's half: the welcome gate before the map, Your key, Export / Import in the domain menu, and the take-over (a `BroadcastChannel("archipelago")` message makes the other tab `release()` its worker). `prepareImport` marks a WAL file (the local tool's) for the rollback journal; `migrationsError` refuses a database from a newer build. `build:web` also writes `_headers` (`headersFile`): a CSP with the inline scripts allowed by hash, `connect-src` only to itself and `api.anthropic.com`, `'wasm-unsafe-eval'` for sqlite and shiki, and `'unsafe-eval'` for function-plot. `@sqlite.org/sqlite-wasm` is a devDependency, so the plugin's install doesn't grow.
- Phones (`max-width: 720px` in `styles.css`): the outline starts as a rail when nothing is stored, the chrome and strip wrap, `--pane-w` is forced to `100vw` so the pane, board, and everything aligned to them take the screen, and the pane head carries **Board** and **Map** links (`.phone-only`) because nothing else reaches them there.
- Page: no framework, no bundler, no `innerHTML`. Pure helpers in `view-model.js`, `thread.js` (markdown, log items), and `camera.js` are unit-tested; the canvas and the pane are checked by hand. The pane (`card.js`) is head, log, foot: the log is the only scroll region. Selecting an island frames it at the centre of the map area beside the pane at 1.5× the home scale (`frameSelection` in `app.js`).
- Map positions live on `islands.x`/`islands.y` in a fixed 1000×1000 world per scale (null = unplaced). The page places unplaced islands once (existing ones pinned) and posts `/api/positions`; the simulation never runs when everything is placed. Names are laid out every frame by `labels.js` (pure): wrapped to `WRAP` box units in at most three lines, then placed below, above, right, or left of the coast, wherever they clear every other name and every other island's lamps; a name with no clear spot is hidden until its island is hovered or selected (those two are placed first). The camera's `fit`/`centreOn` take top and bottom insets too (the header and the bottom card), and `reframe()` refits when those change. Every island at a scale shares one radius (`islandRadius(count)`); it is the coast radius 62 of Contour's 200-unit box (`src/web/contour.js`), so marks scale with the map and elevation never changes size. `draw.js` is stateless and reads derived fields only; the write animations run off `node.litAt` and `node.stateAt`. The palette is Contour's (sea, line at alphas, lamp, reef, sand, grass, snow); the chrome's old token names are aliases onto it.
- Schema changes go in a new numbered migration under `src/core/migrations/` and a line in `migrations/index.ts` (imported as text, so the hosted build bundles them; `db.test.ts` fails if the two drift); `0001_initial.sql` is frozen.
- The judge writes only through its seven tools: `island_context` reads; `set_landmarks`, `unlock_landmark`, `record_verdict` (sandbar, settled, mountainous), `propose_reef`, `ask_reader` (records a question with 2–4 options, attached by the route to the reply), and `board_write` (pins, updates, or removes a card on the island's board; only its own cards) write. A reef is written only when the reader confirms it via `POST /api/probe/reef`.
- `ConflictError` → 409. `POST /api/probe` holds one turn per island at a time.
- Behaviour lives in protocol text before code: the terminal cartographer's in `.claude/skills/archipelago-chart/SKILL.md`, the in-app cartographer's in `src/server/judge/CARTOGRAPHER.md`, the judge's in `src/server/judge/PROTOCOL.md`, the mentor's in `src/server/judge/MENTOR.md`. The sketch numbers (6–10 top-level islands, 4–8 islets, 4–6 landmarks) live in both cartographer files and in `SKETCH_LIMITS`; `tests/server/protocol.test.ts` fails if they drift.
- The tool surface of both personas, judge and mentor, is closed by `tools: []` plus `allowedTools` (from `persona.toolNames`) in `src/server/judge/sdk.ts`, not by `canUseTool`; do not "fix" it back. The API runner sends only `toolDefinitionsFor(persona)` and no server tools, and `runTool` refuses any name outside the persona's list.
- Runners: `createRunner("api" | "sdk" | "stub")`; `defaultJudge()` reads `ARCHIPELAGO_JUDGE`, then `ARCHIPELAGO_STUB=1`, then picks `api` when `ANTHROPIC_API_KEY` is set, else `sdk`. Tool descriptions and input shapes live once in `tool-specs.ts` (no database); `runTool` in `tools.ts` dispatches for both runners. The API runner (`api.ts`) is a manual streaming loop: protocol block cached, context after it, the thread replayed as one user message, `claude-opus-5-5` at `ARCHIPELAGO_EFFORT` (default `high`), server-side refusal fallbacks, at most 16 requests a turn; it reaches the database only through its injected `ToolBox`, and tests drive it with a scripted `openStream`, never the network. On Opus 5.5 text written between tool calls is hidden, so both protocols say: every tool call first, then the whole reply.
- `bun test` never spawns the SDK or calls the API: server tests run with `stub: true`; `createRunner` imports `sdk.ts` and `api.ts` lazily.
- Landmarks are dark or lit, never a state; unique per island. `set_landmarks` only when an island has none; `unlock_landmark` links the latest reader message and writes the system line `landmark lit: <name>`. The judge's verdict lands when all landmarks are lit, a reef is clear, or after the fourth reader answer.
- Mentor mode: two modes, `judge` and `mentor`, one per thread (`messages.mode`, default `judge`; `listMessages(db, island, mode)`). The mentor writes only through its five tools (`island_context`, `set_landmarks`, `mark_explored`, `ask_reader`, `board_write`); no verdict, no lit landmark, no reef. `mark_explored` checks in code that the evidence is a substring of the reader's latest mentor message, at least two words and 12+ characters, and that the message is not a pick from an ask's options (own words typed in place of the options still count). Explored (`landmarks.explored_*`) is never lit, never a score or a state. The judge's context names explored landmarks in one line and never reads the mentor's thread. `POST /api/probe` and `GET /api/thread` take `mode`; the one-turn lock is per island across both modes.
- Cartographer in the app: a third persona (`cartographer`, `chart.ts`) on the same runners, with two tools (`chart_context`, `propose_sketch`). It never writes the map: `propose_sketch` records the scale's pending sketch (`sketches`, migration 0009; one pending per scale, a new one supersedes it), and only `POST /api/sketch` (`approve` | `discard`) writes, through `approveSketch` in `sketchRepository.ts`, which re-validates (a slug taken since is a 409) and writes islands, landmarks, straits, harbour, and updates in one transaction plus the `sketch approved: …` system line. One cartographer thread per scale: `messages.island_id` is null at the domain's top scale (only for `mode = 'cartographer'`), `listScaleMessages`. `POST /api/probe` with `mode: "cartographer"` takes `island` as the scale (absent = top); its lock key is `<domain>/<island>` (shared with the judge and mentor on that island) or `<domain>/` at the top. `POST /api/domains { name, slug? }` creates a domain. `Persona.buildContext(deps)` is how each runner reads a persona's context; `TurnDeps.island` is optional, island tools require it (`onIsland`). The terminal skill checks `sketch list --pending` before sketching a scale.
- Cartographer on the page: `chart.js` owns its pane state and renders into `#pane` when `card.js` hands it over (`isChartOpen()` and no island selected; selecting an island drops it). Opened by the strip's Cartographer cell, Sail closer (`setScale` then `openChart(slug, { start: true })`), Note to cartographer (`openChart(scale, { message })`), and `?chart=start` after New domain (`new-domain.js`, `POST /api/domains`). The snapshot carries the scale's pending `sketch`; `chart-model.js` (pure) turns it into draft islands and straits that `buildNodes`/`buildLinks` append (`draft: true`): laid out by the simulation but never posted to `/api/positions` (`unplaced()` skips them), never hit-tested, their straits hidden, drawn by `drawDraft` as a dashed lamp-coloured coast. Escape closes the pane (`chart` rung, after cursor, before deselect); `⌘↵` there approves the pending sketch, else sends. The CTA offers Approve sketch while one is pending, behind only a reef.
- Migrations that rebuild a referenced table start with `-- foreign_keys: off`; the runner switches the pragma outside the transaction and runs `pragma foreign_key_check` before commit (`0008_mentor.sql`).
- Description: `domains.description` (migrations 0010–0011), the reader's own words on what they want to chart and why, at most 500 characters (`DESCRIPTION_MAX`), null when none.
  - **New domain on the page takes only a description.** `createDomain` makes the domain under a provisional name (`provisionalName`: the first phrase, cut short) with a free slug (`-2`, …) and `provisional = 1`.
  - **The cartographer names it.** Its context says the name is provisional, and it passes `name` in its first top-scale `propose_sketch` (never below the top scale). `approveSketch` applies the name through `nameDomain`, which also takes the name's slug when it is free, and returns `domain`. `decideSketch` in `chart.js` follows a new slug with `location.replace`.
  - **Editing.** **Edit domain…** in the domain menu (under New domain…) (`openDomainEdit`, `POST /api/domains/update`) and `domain update --slug [--name] [--description]` edit both; a name given there is no longer provisional, and the slug stays.
  - **Who reads it.** All three personas read the description (`renderDescription`). The cartographer also reads the About you note. The protocols say what each does with it: the cartographer reads the subject and the angle in it and never puts the angle in the name; the judge pitches its scenarios to it without lowering §3; the mentor picks examples from it.
- Learner: one row (`learner`), its update bumps every domain; `learner show|set`, `/api/learner`, "About you" in the domain menu (`learner.js`). Capped at 1000 characters.
- Lens: `app.mode` (localStorage `mode:<domain>`, `body[data-mode]`, `m`, the strip switch). `view-model.js` derives `marks`, `lamp`, `rollup`, `hidden` per lens so `draw.js` stays stateless; the mentor lens draws no elevation, reef, rollup, or strait, and lights explored lamps in `--explore`, which every theme block defines. `theme.js` pushes eight canvas tokens.
- Harbour: `islands.harbour`, at most one per parent (partial unique index); written only by `harbour set` / `clear`. The snapshot carries `harbour` (slug at the current scale); the strip leads with it; the judge never sees it. Every strip cell carries a hint card (hover, or click to pin; `stripItems` and `HINTS` in `src/web/view-model.js`); the last cell, `Cartographer` (`action: "chart"`), opens the cartographer's pane at this scale and names the pending sketch. The page writes no comments any more; the `comments` table and `comment` CLI stay for the terminal.
- Outline: 232px expanded, 44px rail (`--outline-w`); the camera frames between `insets()` (outline left, pane right). Cross-scale selection is `await setScale(scale)` then `select(slug)`. Rail and expansion state live in `localStorage` under `outline:<domain>`.
- Keys: one focused region at a time (`body[data-focus]`, outline → map → pane on Tab), shown by a lamp line; `keys.js` owns the only window keydown listener (the answer box keeps its own Enter) and dispatches to handlers each region registers; `keys-model.js` is pure (Escape ladder, cursor moves, cheat sheet). Letters are dead in text fields. A key the input method owns (`isImeKey`: `isComposing`, or keyCode 229) is never the page's, so Enter picking a Zhuyin candidate never sends; the pane holds its rebuild while the answer box is composing. Escape's ladder stops a streaming turn (rung `stop`, after sheet, About you, and menu); while a reply streams, Send is Stop. A stop aborts the request; the server stops the persona and keeps no reply. The outline cursor is a slug, never persisted. Inside the board's editor, Tab moves between its fields.
- Asks: `asks` rows attach to the judge message the route stores after the turn (`attachAsks`); a pick goes through `POST /api/probe` with `askId` and becomes the next reader message. Mermaid is served at `/vendor/mermaid.js` from the committed `src/server/vendor/mermaid.min.js`; the page renders closed mermaid fences through DOMParser, never innerHTML. shiki and function-plot are the two bundled libraries, each built once per process through `vendorBundle(name)`: shiki's `Bun.build` runs from `src/server/vendor/shiki-entry.js` and serves `/vendor/shiki.js` with an ETag; the engine is oniguruma, whose wasm is served beside it at `/vendor/onig.wasm` as `application/wasm`; the page renders fences as spans per token (`code.js`), colours live in `--code-*` variables, and the judge's code rule is PROTOCOL §9 (one fence per reply, code, diagram, or plot). The bottom-centre card (`cta.js`) carries map actions only: reef confirm, sail next. Plot fences (`plot`, `function-plot`, `math-plot`) draw through `function-plot`, bundled like shiki by `vendorBundle("plot")` and served at `/vendor/plot.js`; they are static (`disableZoom`), take their colours from `PALETTE`, and are redrawn rather than cached (`src/web/plot.js`, pure parts in `src/web/plot-model.js`). The format is shuttle's, so a body renders in both apps, and the judge's plot rule is PROTOCOL §9.
- Monospace is Paper Mono (SIL OFL 1.1), one variable woff2 in `src/web/fonts/` served as a static file; every code, kbd and editor face goes through `--font-mono` in `:root`, never a literal monospace stack. It is not a colour, so no theme block redefines it (`NOT_COLOURS` in `tests/web/theme-tokens.test.js`).
- Themes: `src/web/theme-model.js` is the registry (`ink` first and default, its values on bare `:root`; then `tide`, `moonlight`, `chart`, `vellum`; a stored id no longer registered, such as the retired `night`, falls back to `ink`); a theme is one entry there plus one `:root[data-theme="<id>"]` block in `styles.css` that redefines every literal colour token of `:root`. The palettes are derived in OKLCH, and every text and mark is checked against the sea, the panel, and `--panel-2` (text at least 4.5:1, marks at least 3:1) (`tests/web/theme-tokens.test.js` enforces it, and that no literal colour exists outside those blocks). `theme.js` stamps `<html>`, stores `localStorage.theme` (per browser, never the database), pushes the eight canvas tokens into `PALETTE` through `setPalette`, re-initialises mermaid on its `base` theme through `applyMermaidTheme` (cache cleared), and fires a `theme` event the pane and the board rebuild on; a head script stamps the stored id before first paint. Picked from the outline's domain menu (one Theme row naming the current theme; a click opens the list) or with `t`. The system colour scheme is never read.
- Board: `board_cards` (migration 0007), one board per island, kinds `diagram | note | code`, authors `you | judge`, creation order. `boardWrite(deps, input, author)` in `tools.ts` carries the rules for both the SDK tool (`judge`: own cards only, one `board: …` system line per write) and `POST /api/board` (`you`: any card, no message). The context renders the whole board with "new/edited since your last reply" marks (PROTOCOL §10). On the page, `board.js` is a sheet over the map area (`#board` below the strip with a scrim `#board-scrim` over the peeked map, z-index 2, toggled by the bottom-right button, `b`, the ×, or a click on the scrim; the map keeps drawing behind it), `board-model.js` is pure; while the board is open it is the map region's container and takes the map's keys (`j/k`, Enter, `d/n/c`, `x`, `⌘↵`); Escape rungs: sheet, menu, blur, editor, board, cursor, deselect. Board writes never start a Keeper turn. `board list --domain --island` is the cartographer's read of the board; the charting skill reads it beside the thread before sailing closer.
