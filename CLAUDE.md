# Archipelago

Chart what you understand about a domain, as islands in open water. Brief: `docs/BRIEF.md`. Slice 1 spec: `docs/superpowers/specs/2026-09-03-archipelago-slice1-design.md`. Plan: `docs/superpowers/plans/2026-09-03-archipelago-slice1.md`.

## Commands

```bash
bun install
bun test                              # all tests (bun test, NOT vitest — vitest cannot resolve bun:sqlite)
bun run test:wasm                     # core, server, web tests again on the WebAssembly SQLite (the hosted build's database)
bunx tsc --noEmit                     # typecheck
bun run src/cli/index.ts <command>    # the CLI; `bun link` registers it as `archipelago`
bun run src/cli/index.ts serve        # map server on 127.0.0.1:4480, opens the browser
bun run src/cli/index.ts serve --stub # judge without a Claude login
bun run src/cli/index.ts serve --judge api   # judge on the Messages API (needs ANTHROPIC_API_KEY)
bun run build:web                     # the hosted build: a static site in dist/web/ (serve it on localhost to try it)
bun run deploy:web                    # build, then `wrangler pages deploy` to the Cloudflare Pages project archipelago (https://archipelago-c24.pages.dev)
bun run src/cli/index.ts export [--out f]   # the whole database as one file (VACUUM INTO); the hosted app imports it
bun run conformance [--judge api|openai|stub] [--models a,b] [--verbose] [--json f]   # thirteen scripted turns per model (judge, mentor, cartographer, loose ends, pointing, zh-TW page) on a throwaway database, checked against the protocols' hard rules; spends real money on a real model
claude plugin validate .              # the plugin and marketplace manifests
claude --plugin-dir .                 # try the plugin from this checkout
```

## Architecture

Two brains, one database. Claude in the terminal is the cartographer (skill → CLI → SQLite): it sketches islands, islets, and straits. The judge runs inside the server (`src/server/judge/`), one thread per island, on one of four runners behind `JudgeRunner`: `api` (Claude on the Messages API, `api.ts`), `openai` (any OpenAI-style chat server: Gemini, OpenAI, OpenRouter, Ollama, `openai.ts`), `sdk` (the Claude Agent SDK, `sdk.ts`), or `stub`, and writes verdicts through the same repositories. The mentor runs on the same runner as a second persona (`src/server/judge/persona.ts`: protocol file, closed tool list, renderers, stub), with its own thread per island (`messages.mode`), its protocol in `MENTOR.md`, and a learner block (solid ground across every domain, confirmed reefs, the note in `learner`) at the top of its context. The browser is the consumer (server → JSON API → canvas page polling `/api/version`) and the judge's chat surface (`POST /api/probe` streaming server-sent events). The outline (`outline.js`) reads `GET /api/outline`, the whole tree, refreshed with every snapshot. Comments and focus flow back through the same database.

## Conventions

- Plugin: the repo root is the plugin. `plugin.json` points `skills` at `./.claude/skills`, so the same SKILL.md serves the plugin and the in-repo project skill; it calls `archipelago`, never `bun run src/cli/index.ts`. Claude Code installs dependencies from `package.json` + `bun.lock` with `--ignore-scripts` and a 60 s limit, so every dependency is pinned exactly and nothing may need an install script. Mermaid is committed at `src/server/vendor/mermaid.min.js` (a devDependency; `bun run vendor:mermaid` refreshes it) because it was the slowest download. Bump `version` in `plugin.json` to ship an update.
- One database per user: `~/.archipelago/archipelago.sqlite` (`DEFAULT_DB_PATH`), `ARCHIPELAGO_DB_PATH` overrides.
- `bun:sqlite`, numbered migrations in `src/core/migrations/`, snake_case columns aliased to camelCase in every `select`. Repositories type their connection as `Database` from `src/core/sql.ts` (the subset they use), never from `bun:sqlite`, so they also run on the WebAssembly adapter `sql-wasm.ts`; `bun run test:wasm` proves it by swapping `openDatabase` for the adapter across the core, server, and web suites.
- Open water is the absence of a verdict. Never store or render an "open" state as a score.
- Verdicts are append-only; latest `id` wins. Island slugs are unique per domain. Straits join siblings only.
- Every write bumps `view_state.version` via SQL triggers; the page polls that integer every 2s.
- CLI: JSON always; pretty on a TTY, compact with `--json` or when piped; `--stdin` merges JSON under flags; errors exit 1 with `{ error, valid? }`.
- Server opens and closes the database per request. Static files are read fresh (`Cache-Control: no-cache`); no build step for the page.
- Hosted build (spec `docs/superpowers/specs/2026-10-20-hosted-byok-design.md`): the same page and the same `/api/` routes, with the server in a Web Worker. `api-routes.ts` holds everything under `/api/` and must stay free of Bun and Node calls; `routes.ts` adds static files and vendor bundles for `archipelago serve`. The page's requests all go through `transport.js` (`request`): `fetch` locally, a message to `/worker.js` when `index.html` sets `ARCHIPELAGO_HOSTED` (only `build:web` does). The worker (`src/hosted/worker.ts`) takes the `archipelago-db` Web Lock, opens SQLite-WASM on OPFS (`opfs-sahpool`) once, migrates, and answers through `handler.ts`; `build-web.ts` swaps three modules for browser twins (`core/db.ts` → `hosted/db.ts`, `judge/protocol.ts` → `hosted/protocol.ts`, `judge/sdk.ts` → `hosted/no-sdk.ts`). Paths under `/hosted/` are the worker's own (`hosted/routes.ts`): `settings` (the provider, one key and one model per provider, remember, stub), `export`, `import`; a database file crosses the transport as bytes (`application/vnd.sqlite3`). The keys live in the worker (`settings.ts`: IndexedDB when remembered, else memory), never in SQLite, and the page reads back only `…abcd`. `PROVIDERS` there is the list a reader can bring a key for: Claude (`createApiRunner({ apiKey, model, hosted: true })`, Sonnet 5.5 by default), Gemini and OpenRouter (`createChatRunner` on their `baseUrl`; each also takes any model id the reader types, `custom`); `activeOf` picks the chosen provider's key and model, and without a key the stub answers. A record saved before providers (one `apiKey`) reads as the Claude key. OpenRouter's `reasoning_details` (Gemini's thought signatures among them) go back on the assistant message with the tool results. `src/web/hosted.js` is the page's half: the welcome gate before the map, Your key (a provider switch, then that provider's key and models), Download a backup / Restore a backup… (export / import) in the domain menu, and the take-over (a `BroadcastChannel("archipelago")` message makes the other tab `release()` its worker). `prepareImport` marks a WAL file (the local tool's) for the rollback journal; `migrationsError` refuses a database from a newer build. `build:web` also writes `_headers` (`headersFile`): a CSP with the inline scripts allowed by hash, `connect-src` only to itself and each provider's host (from `PROVIDERS`), `'wasm-unsafe-eval'` for sqlite and shiki, and `'unsafe-eval'` for function-plot. `@sqlite.org/sqlite-wasm` is a devDependency, so the plugin's install doesn't grow.
- Phones (`max-width: 720px` in `styles.css`): the outline starts as a rail when nothing is stored, the chrome and strip wrap, `--pane-w` is forced to `100vw` so the pane, board, and everything aligned to them take the screen (elsewhere the pane opens at half the window, `clamp(340px, 50vw, 960px)`, until the grip stores a width), and the pane head carries **Board** and **Map** links (`.phone-only`) because nothing else reaches them there. On touch the map takes every gesture (`touch-action: none`): one finger pans or drags, two fingers pinch (`pinchStep`), and a finger held still for `LONG_PRESS_MS` (a lamp ring fills, `app.press`) stands in for double-click and shift: on lift it gathers an island, renames a sea, or names one on the water (`pressAction`, all in `gesture-model.js`, pure). The field opens on lift because a phone shows its keyboard only from a touch the reader ends.
- Page: no framework, no bundler, no `innerHTML`. Pure helpers in `view-model.js`, `thread.js` (markdown, log items), and `camera.js` are unit-tested; the canvas and the pane are checked by hand. The pane (`card.js`) is head, log, foot: the log is the only scroll region. Selecting an island frames it at the centre of the map area beside the pane at 1.5× the home scale (`frameSelection` in `app.js`).
- Map positions live on `islands.x`/`islands.y` in world units (null = unplaced). The sea has no edge: nothing clamps a position (the validator's ±`COORDINATE_MAX` only stops runaway values); `WORLD = 1000` is the unit a fresh scale is laid out in, not a wall. Positions are the reader's own arrangement of the domain, so nothing but the reader moves a placed island. Home (`fit` with `homeBounds()`) frames the islands at this scale with room for their names, never closer than `MAX_HOME`; it grows to take in new islands once they settle if the reader has not moved the map, and is otherwise recomputed on `0` / Escape. A new island starts beside its placed strait neighbours, else just outside the reader's islands; the simulation's gravity centres on the placed ones. Dragging an island to the edge of the map area pans the sea under it (`edgePan` in `interactions.js`). Shift-click gathers an island or a sea name into a group, and shift-drag on the water gathers everything in a box (`group-model.js`, pure; `app.group`, a dashed lamp ring); dragging any member moves them all, saved as one positions post plus each sea. Panning keeps the group, a plain click outside it or Escape (`group` rung, before `sea`) lets it go. The page places unplaced islands once (existing ones pinned) and posts `/api/positions`; the simulation never runs when everything is placed. Names are laid out every frame by `labels.js` (pure): wrapped to `WRAP` box units in at most three lines, then placed below, above, right, or left of the coast, wherever they clear every other name and every other island's lamps; a name with no clear spot is hidden until its island is hovered or selected (those two are placed first). The camera's `fit`/`centreOn` take top and bottom insets too (the header and the bottom card), and `reframe()` refits when those change. Every island at a scale shares one radius (`islandRadius(count)`); it is the coast radius 62 of Contour's 200-unit box (`src/web/contour.js`), so marks scale with the map and elevation never changes size. `draw.js` is stateless and reads derived fields only; the write animations run off `node.litAt` and `node.stateAt`. The palette is Contour's (sea, line at alphas, lamp, reef, sand, grass, snow); the chrome's old token names are aliases onto it.
- Schema changes go in a new numbered migration under `src/core/migrations/` and a line in `migrations/index.ts` (imported as text, so the hosted build bundles them; `db.test.ts` fails if the two drift); `0001_initial.sql` is frozen.
- The judge writes only through its nine tools: `island_context` reads; `set_landmarks`, `unlock_landmark`, `record_verdict` (sandbar, settled, mountainous), `propose_reef`, `ask_reader` (records a question with 2–4 options, attached by the route to the reply), `board_write` (pins, updates, or removes a card on the island's board; only its own cards), `loose_end`, and `point_to` write. A reef is written only when the reader confirms it via `POST /api/probe/reef`.
- `ConflictError` → 409. `POST /api/probe` holds one turn per island at a time.
- Language: each persona's protocol has a `## Language` section: the reader's latest message decides; with none (an opening) or no clear sign, the page's language (the context line says so in as many words, since Gemini otherwise follows the English around it), then the description's, then the thread's; keep Traditional Chinese Traditional, names in that language, slugs ASCII kebab and never in a reply.
- Behaviour lives in protocol text before code: the terminal cartographer's in `.claude/skills/archipelago-chart/SKILL.md`, the in-app cartographer's in `src/server/judge/CARTOGRAPHER.md`, the judge's in `src/server/judge/PROTOCOL.md`, the mentor's in `src/server/judge/MENTOR.md`. The sketch numbers (6–10 top-level islands, 4–8 islets, 4–6 landmarks) live in both cartographer files and in `SKETCH_LIMITS`; `tests/server/protocol.test.ts` fails if they drift.
- The tool surface of both personas, judge and mentor, is closed by `tools: []` plus `allowedTools` (from `persona.toolNames`) in `src/server/judge/sdk.ts`, not by `canUseTool`; do not "fix" it back. The API runner sends only `toolDefinitionsFor(persona)` and no server tools, and `runTool` refuses any name outside the persona's list.
- Runners: `createRunner("api" | "openai" | "sdk" | "stub")`; `defaultJudge()` reads `ARCHIPELAGO_JUDGE`, then `ARCHIPELAGO_STUB=1`, then picks `api` when `ANTHROPIC_API_KEY` is set, else `sdk`. Tool descriptions and input shapes live once in `tool-specs.ts` (no database); `runTool` in `tools.ts` dispatches for both runners. The model runners share one loop (`loop.ts`, `createModelRunner`): it builds the vendor-neutral `TurnRequest` (protocol, context, thread prompt, `toolSpecsFor`), streams text, runs tool calls through its injected `ToolBox`, sends results back, re-issues a response whose tool input will not parse (twice), and stops at 16 requests a turn; a `ModelAdapter` holds what is a vendor's (request shape, stream events, how results go back, `describeError`). `api.ts` is Claude's adapter (`claudeAdapter`; protocol block cached, context after it, the thread as one user message, `claude-opus-5-5` at `ARCHIPELAGO_EFFORT` (default `high`), server-side refusal fallbacks), driven in tests by a scripted `openStream`. `openai.ts` is the OpenAI-style chat adapter (`chatAdapter`: plain `fetch`, its own SSE reading, protocol and context as one system message, tools as functions through `portableSchema`, which strips what Gemini's endpoint refuses, vendor fields on tool calls such as Gemini's thought signature sent back as received; on Gemini it asks for thought summaries (`include_thoughts`) and drops them, because Gemini sends nothing, not even headers, until it has thought, and its server cuts a stream silent for 60 s; `ARCHIPELAGO_EFFORT` becomes Gemini's `thinking_level`, elsewhere `reasoning_effort` (`chatEffort`; unset leaves the model's default, which on Gemini 3.8 Flash judges noticeably stricter than `low`)), driven in tests by a scripted `fetch`. `serve --judge openai` reads `ARCHIPELAGO_BASE_URL` (a URL, or `gemini` / `openai` / `openrouter` / `ollama`), `ARCHIPELAGO_API_KEY` (else that provider's own variable, e.g. `GEMINI_API_KEY`), and `ARCHIPELAGO_MODEL` (no default). Neither test suite touches the network. On Opus 5.5 text written between tool calls is hidden, so both protocols say: every tool call first, then the whole reply.
- Conformance (`scripts/conformance.ts`): `SCRIPT` is the turns, `seed` the database (a zh-TW page; Caching with four landmarks, Indexes with none, a provisional domain), `checkTurn` the rules. FAIL: a turn error, a required tool missing, a tool call the toolbox refused, a non-verbatim quote, the wrong language (`cjkShare`), more question marks than allowed, a hyphenated slug or TeX in the prose, Simplified characters, no verdict or reef by the fourth answer. WARN: a hoped-for tool (`propose_reef` on the wrong claim, `loose_end` closing when an answer clears it up), `island_context` before the first write, no question, a `point_to` that names another island than `point` (FAIL), a reply that touches none of `about` (the Keeper's probe after the mentor noted a loose end). Its test runs the whole script on the stub. Run it on a model before offering that model in the hosted picker (`PROVIDERS` in `src/hosted/settings.ts`).
- `bun test` never spawns the SDK or calls the API: server tests run with `stub: true`; `createRunner` imports `sdk.ts` and `api.ts` lazily.
- Model shown: `ApiContext.model()` names the model the runner answers on right now (null for the stub): `startServer` from `judgeModel(judge)` (a test passes `model` beside its `runner`), the hosted worker from Your key (none without a key). `GET /api/judge` returns `{ model }`; `streamTurn` reads it as a turn starts and stores it on the persona's reply (`messages.model`, migration 0016; null for the reader, system lines, the stub, and replies older than the column). On the page, `model-label.js` reads it at start, after each turn, and on the `settings` event `hosted.js` fires after a settings write; every pane's foot names it beside the key hints (`modelEl`), and `logItems` puts a model line (`kind: "model"`, "<model> from here") before a persona reply whose model differs from the reply before it (never before a thread's first reply, nor for a reply with no model).
- Landmark terms: `landmarks.terms` (migration 0015, a JSON array, null when none) holds 2–5 words a reply uses for the landmark, in the reader's language plus the English term where the field writes it in English. `set_landmarks`, the sketch's landmarks, and `landmark add --terms a,b` write them (`termsSchema`: at most `TERMS_MAX`, deduplicated; an upsert without terms keeps the ones it has, so `landmark add` on an existing slug is how the terminal backfills them). The snapshot carries `terms` on each landmark; `term-model.js` (pure) turns them into `landmarkTerms` (a landmark with none gets words from its name: `deriveTerms`) and `termRuns`; `renderMarkdown(…, { terms })` marks them `.term` in the persona's replies (never in code or the reader's messages), and hovering a word or its chip lights both (`lightLandmark` in `card.js`). Terms are for the page only; no persona's context reads them.
- Landmarks are dark or lit, never a state; unique per island. `set_landmarks` only when an island has none; `unlock_landmark` links the latest reader message and writes the system line `landmark lit: <name>`. The judge's verdict lands when all landmarks are lit, a reef is clear, or after the fourth reader answer.
- Mentor mode: two modes, `judge` and `mentor`, one per thread (`messages.mode`, default `judge`; `listMessages(db, island, mode)`). The mentor writes only through its seven tools (`island_context`, `set_landmarks`, `mark_explored`, `ask_reader`, `board_write`, `loose_end`, `point_to`); no verdict, no lit landmark, no reef. `mark_explored` checks in code that the evidence is a substring of the reader's latest mentor message, at least two words and 12+ characters or 6+ CJK characters (`isRecognisableQuote`; Chinese has no spaces), and that the message is not a pick from an ask's options (own words typed in place of the options still count). Explored (`landmarks.explored_*`) is never lit, never a score or a state. The judge's context names explored landmarks in one line and never reads the mentor's thread. `POST /api/probe` and `GET /api/thread` take `mode`; the one-turn lock is per island across both modes.
- Loose ends (`loose_ends`, migration 0017): what the reader found confusing (`confused`), asked and left open (`asked`), or means to come back to (`later`), on one island, tied to a landmark or to the island as a whole. Shared memory between the two personas: either notes one with `loose_end` (`op: open`, a one-line note in the reader's language: what went wrong and what was explained) and either closes any open one (`op: close`); both read the open ones (`renderLooseEnds`, PROTOCOL §11, MENTOR §10). The evidence is checked in code like `mark_explored`'s (`isRecognisableQuote`, a substring of the reader's latest message in the writer's own thread). At most `LOOSE_OPEN_MAX` (6) open per island. Each write leaves `loose end: <note>` / `loose end closed: <note>` in the writer's thread (`systemText` translates; the line keeps its case). Never evidence for a lit landmark or a verdict, never a reef: the Keeper probes whether it held, the mentor takes it up when the reader comes near it. The snapshot carries the open ones (`looseEnds`, landmark as a slug); the pane marks a landmark chip with `?` (the island's own after the chips), a click unfolds them, and Dismiss posts `POST /api/loose-ends` (closed by `you`, no line). `loose-end list --domain --island [--all]` in the terminal.
- Pointing elsewhere (`pointers`, migration 0018): when the reader's words belong to another island of the domain, the Keeper or the mentor calls `point_to` (`island`: any other island's slug, from `Islands elsewhere` in both contexts, one line per scale (`renderElsewhere`); `why`: one line). PROTOCOL §12: say so, light nothing from it, keep the question on this island. MENTOR §11: answer in two or three sentences, then point. The pointer stores the reader's latest message in that thread as `question`, and the route attaches it to the turn's reply like an ask (`pointerFloor`, `attachPointers`); `GET /api/thread` returns `pointers` for that thread. On the page a "Sail to <name>" card sits under the reply (`sailEl`); a click changes scale if needed and selects the island in the same lens (`sailTo`). From the mentor it also carries the question (`carry`): on an island whose mentor thread is empty, the briefing shows it and starts with it (Ask the mentor this, or Start without it); otherwise it goes into the answer box as a draft. The Keeper's pointer carries nothing, since a question there would spend one of its four answers.
- Cartographer in the app: a third persona (`cartographer`, `chart.ts`) on the same runners, with two tools (`chart_context`, `propose_sketch`). It never writes the map: `propose_sketch` records the scale's pending sketch (`sketches`, migration 0009; one pending per scale, a new one supersedes it), and only `POST /api/sketch` (`approve` | `discard`) writes, through `approveSketch` in `sketchRepository.ts`, which re-validates (a slug taken since is a 409) and writes islands, landmarks, straits, harbour, and updates in one transaction plus the `sketch approved: …` system line. One cartographer thread per scale: `messages.island_id` is null at the domain's top scale (only for `mode = 'cartographer'`), `listScaleMessages`. `POST /api/probe` with `mode: "cartographer"` takes `island` as the scale (absent = top); its lock key is `<domain>/<island>` (shared with the judge and mentor on that island) or `<domain>/` at the top. `POST /api/domains { name, slug? }` creates a domain. `Persona.buildContext(deps)` is how each runner reads a persona's context; `TurnDeps.island` is optional, island tools require it (`onIsland`). The terminal skill checks `sketch list --pending` before sketching a scale.
- Cartographer on the page: `chart.js` owns its pane state and renders into `#pane` when `card.js` hands it over (`isChartOpen()` and no island selected; selecting an island drops it). Opened by the strip's Cartographer cell, Sail closer (`setScale` then `openChart(slug, { start: true })`), Note to cartographer (`openChart(scale, { message })`), and `?chart=start` after New domain (`new-domain.js`, `POST /api/domains`). The snapshot carries the scale's pending `sketch`; `chart-model.js` (pure) turns it into draft islands and straits that `buildNodes`/`buildLinks` append (`draft: true`): laid out by the simulation but never posted to `/api/positions` (`unplaced()` skips them), never hit-tested, their straits hidden, drawn by `drawDraft` as a dashed lamp-coloured coast. While the cartographer works on a scale with no islands, the map's middle shows it at work (`drawSketching` in `draw.js`, screen px, still under reduced motion): three coasts trace in lamp, dotted straits join them, then it fades and redraws, over `Sketching <name>` and the step. In every pane the waiting line names the step in plain words (`progress-model.js`: `STEPS`, one per tool, a test keeps them complete) and shimmers with pulsing dots (`thinking.js`). Escape closes the pane (`chart` rung, after cursor, before deselect); `⌘↵` there approves the pending sketch, else sends. The CTA offers Approve sketch while one is pending, behind only a reef.
- Migrations that rebuild a referenced table start with `-- foreign_keys: off`; the runner switches the pragma outside the transaction and runs `pragma foreign_key_check` before commit (`0008_mentor.sql`).
- Description: `domains.description` (migrations 0010–0011), the reader's own words on what they want to chart and why, at most 500 characters (`DESCRIPTION_MAX`), null when none.
  - **New domain on the page takes only a description.** `createDomain` makes the domain under a provisional name (`provisionalName`: the first phrase, cut short) with a free slug (`-2`, …) and `provisional = 1`.
  - **The cartographer names it.** Its context says the name is provisional, and it passes `name` in its first top-scale `propose_sketch` (never below the top scale). `approveSketch` applies the name through `nameDomain`, which also takes the name's slug when it is free, and returns `domain`. `decideSketch` in `chart.js` follows a new slug with `location.replace`.
  - **Editing.** the pencil on the current domain's row in the domain menu (shown on hover or focus, always on touch screens) (`openDomainEdit`, `POST /api/domains/update`) and `domain update --slug [--name] [--description]` edit both; a name given there is no longer provisional, and the slug stays.
  - **Deleting.** **Delete domain…** in the same dialog asks once (what goes with it; hosted, a pointer to the backup), then `POST /api/domains/delete` (`removeDomain`: every table cascades from `domains`; 409 while a turn runs in the domain) and the page opens whichever domain is left. `domain remove --slug` in the terminal, only when the user asks.
  - **Who reads it.** All three personas read the description (`renderDescription`). The cartographer also reads the About you note. The protocols say what each does with it: the cartographer reads the subject and the angle in it and never puts the angle in the name; the judge pitches its scenarios to it without lowering §3; the mentor picks examples from it.
